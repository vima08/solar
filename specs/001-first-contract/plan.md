# План 001 — Первый оплачиваемый рейс

Статус: реализован, awaiting-playtest. Объём с дополнениями одобрен владельцем 2026-10-31. Независимый критик `slice_plan_review` подтвердил READY после уточнения атомарного снимка и единого таймера; отдельный `slice_result_review` проверил реализацию.

## Наблюдения по репозиторию

`js/ui/expedition.js` сейчас объединяет полёт, посадку, три экспедиционные миссии и сохранение через `kosmodrom-expedition-v1`. `js/core/engine.js` вызывает обновление экспедиции каждый кадр. Новую экономику не следует реализовывать покадровыми изменениями DOM или дописывать целиком в экспедицию.

## Предлагаемые правила сохранения

Версия `career` — 1. Раздел отсутствует: создать available, 0 кредитов, пустой контрактный отсек. Вместимость 2 хранится в конфигурации, а не доверяется сохранению. Это не затрагивает груз старой экспедиционной цепочки.

Предлагаемая схема: `career = { version: 1, credits: 0, contractStatus: "available", cargo: [], flightSeconds: 0 }`. Статус — available, active или completed. `cargo` — массив `{ contractId: "earth-mars-equipment", quantity: 1 }`; active содержит ровно одну такую запись, остальные статусы — пустой массив. `flightSeconds` — конечное число от 0 до 300, неверное значение восстанавливается в 0 с предупреждением. Cargo этого среза принадлежит только новому контракту.

Присутствующий раздел неверного типа (включая null/массив), отсутствующая/нецелая версия или версия меньше 1 считаются повреждением: подготовить defaults с предупреждением и барьером записи до решения игрока. Целая версия больше 1 — несовместимая будущая версия с полным запретом записи. В версии 1 неверный тип cargo восстанавливается по статусу; неверный credits и contractStatus — по таблице ниже. Неизвестные поля версии 1 сохранять при обновлении объекта.

| Вход | Нормализация без начисления награды |
| --- | --- |
| Баланс — не целое неотрицательное безопасное число | 0 и предупреждение о восстановлении данных |
| Неизвестный статус контракта | available, удалить только груз этого контракта, показать предупреждение |
| active, груз отсутствует или дублирован | Ровно одна единица контрактного груза |
| available или completed, остался контрактный груз | Удалить этот груз, баланс не увеличивать |
| Неизвестные предметы в новом контрактном отсеке | Не загружать их; показать предупреждение, не менять другие разделы сохранения |
| Неизвестная будущая версия career | Не перезаписывать сохранение; отключить изменения карьеры и объяснить несовместимость |

Перед восстановлением повреждённого раздела предложить экспорт исходной записи; не выполнять автоматическую запись нормализованной версии до действия игрока. Подробность сообщения и экспорт реализовать только для повреждённых данных. Отказ записи при штатном действии оставляет согласованное состояние в памяти с явным статусом «не сохранено»; перезагрузка возвращает последнюю успешную запись. Повторная сдача в той же сессии запрещена статусом completed.

Все записи в `kosmodrom-expedition-v1`, включая периодическое сохранение, посадку, восстановление корабля и обработчики ухода со страницы, проходят единый барьер записи. При неизвестной будущей версии блокировать запись всего объекта, отключать действия карьеры и явно предупреждать, что текущая сессия не сохраняется. При повреждённых данных блокировать всю запись до явного действия «Применить восстановление» после предложения экспорта; простое перемещение или посадка таким согласием не считаются. До решения продолжать полёт в памяти с предупреждением. Покрыть оба барьера тестами повторного автосохранения и перезагрузки.

## Риски и уточнения до реализации

- На Марсе одна посадка может продвинуть старую миссию; сдача нового контракта остаётся отдельным явным действием. Проверить оба прогресса независимо.
- Правила нормализации выше — предложение для согласования вместе с планом. Для active один груз всегда помещается во вместимость 2; посторонние предметы в этом срезе не поддерживаются.
- Предлагаемая вместимость 2 — параметр первого контракта; распространение ограничения на старые миссии в объём не входит.
- Изменение сохранений проверить на копиях фикстур. При откате кода старые поля экспедиции должны оставаться читаемыми; новые поля нельзя автоматически удалять.

## Дополнения владельца: полёт, сенсорный ввод и файлы

- **R9:** модуль контракта определяет длительность 300s и вычисляет остаток. Контрактный автопилот использует единый счётчик активного времени для положения корабля, `flightSeconds`, отсчёта и радиоэтапов. Источник — разность `performance.now()` кадров, независимо от физического ограничения delta в 0.05; на pause/visibilitychange сбрасывать отметку времени, не учитывать промежутки паузы и скрытия. Экспедиция увеличивает счётчик только при активном контрактном автопилоте к Марсу, видимой вкладке и снятой паузе; сохраняет прогресс. Отмена оставляет накопленное время; возобновление строит переход из текущей позиции за остаток (минимум 8s для подлёта, если круиз уже завершён). Не добавлять ожидание на сдаче. Три радиоэтапа и понятный обратный отсчёт сопровождают перелёт. Существующие 8s-переходы не менять вне этого контракта. Проверить редкие кадры, паузу, скрытие, отмену и возобновление после загрузки.
- **R10–R11:** `js/ui/touch-controls.js` обрабатывает Pointer Events с capture отдельно для каждого стика, ограничивает вектор единичным кругом и вводит мёртвую зону. `ship-controls.js` смешивает оси с клавиатурой, сохраняя аналоговую силу тяги. Сбрасывать ввод на всех путях отключения; при открытом пульте/диалоге стики скрыты. Сенсорность определять через `any-pointer: coarse`/touch points; в настройках оставить переключатель для гибридных устройств. CSS учитывает safe area, планшетные ориентации и минимум 44px для элементов управления. Новый контракт открывается отдельной кнопкой журнала без необходимости знать горячие клавиши.
- **R12:** `js/game/save-files.js` задаёт envelope `{ format: "kosmodrom-save", version: 1, expedition, exploration }`, размер до 1 MiB. В браузере использовать ОДНУ авторитетную запись `kosmodrom-expedition-v1`: существующие поля + career + exploration. Импорт одной атомарной setItem заменяет весь снимок; ошибка сохраняет прежнюю запись, откат нескольких ключей не нужен. До импорта синхронизировать экспорт со снимком в памяти; после успешного импорта блокировать pagehide/autosave старой сессии до reload. Только известные поля входят в импорт, остальные localStorage-ключи не затрагиваются. Валидировать типы, конечность/длины векторов, fuel, landedOn/target по существующим телам, mission index, samples и всю career; повреждённую career отклонять, не восстанавливать молча. Отсутствующая career мигрируется в defaults. Импорт: файл → проверка → сводка в dialog → подтверждение → одна запись → перезагрузка. При ошибке записи оставить сессию и исходную запись неизменными, показать ошибку. До изменений предложить скачать текущую копию. Экспорт при барьере восстановления отдаёт исходную запись как резервную копию; повреждённая копия не объявляется пригодной для игрового импорта.
- **Проверки:** добавить отдельные тесты переходов и валидации на том же Playwright, полноценный browser round-trip файла с отменой и ошибками; сенсорные тесты одновременных указателей/сброса. Полный контрактный круиз проверить отдельно от быстрых регрессий, не ускоряя продуктовые часы в production.
